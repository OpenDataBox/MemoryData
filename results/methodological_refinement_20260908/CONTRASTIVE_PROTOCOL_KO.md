# 비슷한 사건을 구분하는 원문 메모리 대조

코드와 선택 기준의 SHA256을 원격 `contrastive_precommit.json`에 **1788804328.2804244** 시각으로 고정했다. 당시 독립 100문항 checkpoint는 source 효용 측정 중이었고 메모리 선택 고정이나 새 질문 평가에 도달하지 않았다. 이후 checkpoint 점수·예측·캐시는 이 구성에 입력하지 않는다.

가설은 비슷한 사건의 별도 속성을 명시한 검색 키가, 동일한 두 원문을 단순 결합한 검색 키보다 사건 간 잘못된 연결을 줄일 수 있다는 것이다. 이는 검증할 가설이며 새로운 기법이나 효과가 입증된 상태가 아니다.

개발 7개 대화의 고정 r40 unit embedding으로 다른 세션이면서 출처가 겹치지 않는 유사한 쌍을 제안한다. 양의 cosine을 큰 순서로 보고 각 unit 차수는 2, 대화당 제안은 64개로 고정한다. 이 일반적 구조 가정은 benchmark 질문이나 실패 사례에 맞춰 정하지 않았다. Qwen3-8B의 구조화 출력으로 두 사건이 구분되는지 판단하고 짧은 사실 비교 키를 작성한다.

새 키의 생성·검증에는 r40의 생성된 사실 문구 대신 **그 unit이 가리킨 원본 발화와 원래 세션 날짜**를 넣는다. 같은 사건, 무관한 내용, 불확실한 구분은 저장 후보로 쓰지 않는다. 별개 사건으로 판정한 키도 원문에서 주체·사건·시점이 제대로 귀속되는지 같은 모델이 추가 검사한다. 이 검사는 self-verification이며 사람의 사실성 인증이 아니다. 원문에 없는 날짜·차이·모순을 추가하지 않는다.

후보 선택은 similarity/common-cost 비율의 greedy 방식이다. 새로운 쌍끼리는 출처를 공유하지 않으며 대화별 추가 2000 또는 4000토큰 안에서 선택한다. Common cost는 구분 키와 실제 원문 payload 모두의 토큰 비용이다. 이 비용으로 고른 **동일 pair ID**에 대해 literal(원문 결합으로 검색)과 contrastive(생성한 구분 키로 검색)를 비교한다. 실제 쓰는 토큰 수 차이는 별도로 보고한다. 네 대조군 모두 최고 parent 메모리를 유지한다. 검색기·reader·2048-token 읽기 상한을 바꾸지 않는다. Greedy 선택은 최적 matching이라고 주장하지 않는다.

선택용 진단은 동일한 75개 source 사실의 Q0와 A 표현이다. 기존 source 97개와 A 75개의 크기 차이를 섞지 않는다. 주 선택은 두 표현 모두 보존 답 수가 순증가한 후보 중 작은 쪽의 순증가, 전체 순증가, 낮은 저장량 순으로 고른다. 개별 문항 퇴행은 허용하되 회복과 퇴행을 각각 기록한다. 기존의 개별 퇴행 0 조건으로 고른 선택도 비교용으로 동시에 고정한다. 둘 다 새로운 개발 점수를 보기 전에 고정한다. 해당 조건을 만족하는 후보가 없으면 최고 parent를 유지한다. 개발 네 대조 결과와 두 source 선택의 결과는 구분해 보고한다.

사건 그래프 자체는 [CompassMem](https://aclanthology.org/2026.findings-acl.1123/)의 사건·논리 관계 구조와 겹친다. 대조되는 기억으로 정보량을 높이는 아이디어도 [contrastive translation memories](https://arxiv.org/abs/2212.03140)에 선례가 있다. 현재 주장은 더 좁다. 같은 payload·같은 선택 쌍·같은 읽기 제한에서 원문에 근거한 사건 구분 키의 효과와, 여러 질문 표현에 걸친 source 선택의 전이를 검증한다. 초록 수준 검토만으로 독창성을 결론내리지 않는다.
