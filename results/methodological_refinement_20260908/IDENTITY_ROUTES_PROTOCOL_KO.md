# 같은 사실·같은 예산에서 읽기 본문 사본의 영향 비교

기존 최고 메모리의 읽기 본문을 유지하면서, source 사실을 새 검색 경로로 노출하는 위치를 비교한다. 원문에서 검증했던 SUPPORTED 후보 3,745개와 직전 실험의 임베딩·커버리지 행렬을 그대로 사용한다. 모든 출처 ID가 해당 기존 unit 안에 있는 사실만 후보가 된다. 같은 모델의 지지 판정은 사실성 인증이 아니다.

2000/4000 추가 토큰 예산마다 세 조건을 구성한다.

- **copy**: 사실 키와 기존 본문 사본을 새 unit으로 추가한다.
- **union**: 기존 unit의 검색 키 뒤에 줄바꿈과 사실 키를 붙인다. 읽기 unit은 추가하지 않는다.
- **replace**: 기존 unit의 검색 키를 사실 키로 바꾼다. 기존 키를 잃는 효과를 보는 대조군이며 읽기 unit은 추가하지 않는다.

세 조건에서 읽기 본문·출처·세션은 보존한다. 기존 메모리에 이미 있던 중복까지 제거하는 실험은 아니다. 검색 키를 바꾸면 dense embedding과 BM25 및 읽기 순서가 바뀐다. Reader, RRF, 2048-token packer는 고정한다.

각 후보의 공통 비용은 `max(1, copy 저장비용, union 증분 저장비용, replace 증분 저장비용)`이다. 모든 비용은 실제 tokenizer로 계산하고, 서로 다른 검색 키와 읽기 본문을 모두 센다. 이 공통 비용당 의미적 커버리지 순증가로 탐욕 선택하며 새 선택끼리 출처가 겹치지 않게 한다. 따라서 예산별 세 조건의 **선택 사실·부모 unit·공통 예산은 정확히 동일**하다. 실제 사용 저장량은 다를 수 있어 별도로 보고한다. 벡터 배열 바이트도 따로 기록한다.

여섯 메모리를 hash로 고정한 다음 같은 사실의 Q0/A 75개씩으로 source 답 보존을 평가한다. 양쪽 표현에서 모두 순증가한 후보가 있을 때 최소 순증가, 총 순증가, 작은 실제 저장량 순으로 선택하고, 없으면 기준을 유지한다. 선택을 다시 고정한 뒤 개발 70문항을 평가한다. 기존 audit100, 노출된 B, 미사용 source audit은 구성·선택에 사용하지 않는다. 공개 데이터 JSON 파싱 후 QA를 제거하며, QA bytes를 전혀 로드하지 않는다고 주장하지 않는다.

이 비교는 검색 단서 선택과 본문 사본의 영향을 구분하기 위한 실험이다. 새로운 학술 방법이나 미사용 질문의 일반화가 입증된 것은 아니다. Facility location·검색 키 확장은 기존 방법이며, 커버리지 개선은 답변 F1 개선을 보장하지 않는다.
