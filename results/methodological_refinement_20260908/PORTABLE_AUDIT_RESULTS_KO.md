# 고정 정책의 새 100문항 검증

최초 100문항과 겹치지 않는 새 질문에서, 정책 및 세 방법의 메모리를 모두 고정한 뒤 평가했다. 대상 대화 3개는 최초 pilot에 등장했던 대화이므로 미사용 대화의 일반화 점수는 아니다. 아래 결과로 방법을 선택하거나 다음 refinement를 조정하지 않는다.

| 방법 | 새 100문항 F1 | 저장 토큰/질문 평균 | 읽기 토큰 |
|---|---:|---:|---:|
| seed | 53.37 | 76,665 | 2,036 |
| r40_fused_four_turn | 54.40 | 63,180 | 2,024 |
| s_parent_single_2000 | 54.84 | 65,108 | 2,023 |

고정 parent 정책과 r40의 차이는 **+0.44점**이다. 대화별 bootstrap 95% 구간은 [-1.00, +2.28]점이며, 대화가 3개뿐이므로 추론의 한계가 크다.

| 대화 | seed F1 | r40 F1 | 고정 parent F1 |
|---|---:|---:|---:|
| conv-42 | 58.62 | 57.52 | 59.80 |
| conv-47 | 48.32 | 52.12 | 52.12 |
| conv-50 | 53.01 | 53.45 | 52.45 |

300개 새 질문 예측과 70개 기준 재현 예측을 재채점했다. 공개 원문에서의 source corpus 및 probe 재컴파일, 136개 source-fit probe와 6,317개 확률 추적, source session audit 미사용, 문항 분리, 메모리 hash, 저장·읽기 상한 및 평가 전 고정을 검증했다.
저장 토큰 표는 평가 질문 빈도로 가중한 평균이다. parent의 추가 저장 상한은 r40보다 대화당 2000토큰이며 실제 사용량은 다를 수 있다. 서로 다른 저장 예산을 같은 비용이라고 해석하지 않는다.
질문 단서는 해당 대화 원문에서 생성했으며 벤치마크 질문·정답을 구성 함수에 넘기지 않았다. Source 생성·검증은 같은 Qwen 계열 모델에 의존한다. 이 checkpoint 이후에도 개발 7개 대화의 연구는 계속하되 이 100문항의 개별 실패에 맞춰 조정하지 않는다.

데이터 접근 범위: 준비 단계는 원본 JSON 전체를 파싱한 뒤 대상 대화의 source 세션만 추출했다. 따라서 파일 바이트나 QA 문자열이 프로세스 메모리에 전혀 로드되지 않았다는 뜻은 아니다. 고정 protocol의 QA 미입력 문구는 해당 벤치마크 QA 필드를 준비·구성·선택 입력으로 사용하지 않았다는 데이터 흐름상의 범위로 해석한다. 개별 새 질문과 정답을 평가 입력으로 추출한 시점은 메모리 고정 이후다.
