# 원문 인용으로 읽기 payload 구성

벡터 정렬 실험은 source 질문에서의 개선이 개발 F1 개선으로 이어지지 않았다. 이번에는 기존 최고 메모리의 검색 키와 unit 순서를 고정하고, reader에 전달하는 본문을 구성한다. 원문 focus의 정보는 보존한다.

각 source-ID 묶음에 앞뒤 최대 두 턴을 참고 문맥으로 제공한다. 전체 원문 문맥은 2048토큰 이내다. 같은 Qwen3-8B가 최대 네 사실 문장을 생성하며, 각 문장은 source ID와 원문의 정확한 인용을 가져야 하고 focus 턴을 하나 이상 인용해야 한다. 원문에서 주장하지 않은 완료 사건, 인물·시간의 잘못된 연결, 이미지에서의 정체성 추론을 금지하는 생성 지시를 사용한다. 인용의 정확한 문자열 일치는 코드로 검증한다.

각 문장에 두 진단을 수행한다. 첫째, 인용한 원문 턴만으로 문장 전체가 지지되는지 확인한다. 둘째, 참고 문맥에서 그 인용 턴들을 제거했을 때도 지지되는지 확인한다. 같은 모델이 SUPPORTED / CONTRADICTED / INSUFFICIENT를 판정한다. 문자 일치는 의미 지지의 증명이 아니고, 이 모델 판정이나 삭제 민감성도 사실성·인과성 인증이 아니다. 같은 사실이 다른 턴에 반복되어 있으면 참인 문장도 삭제 민감성 조건에 실패할 수 있다.

동일하게 고정한 검색 키에서 네 조건을 비교한다.

초기 v1은 384토큰 출력 한도에서 첫 대화 196개 중 56개가 JSON을 끝맺지 못해 중단하고 원래 프로토콜·출력·캐시를 보존했다. 별도 v2는 완전한 초기 결과를 그대로 재사용하고, 불완전한 JSON만 같은 원문·지시·schema에서 768, 이어서 1536토큰 한도로 재시도한다. 모든 시도 기록을 남긴다. 이미 완성된 JSON의 인용이 부정확한 경우에는 재시도하지 않고 기존 인용 검증으로 걸러낸다. 완료된 첫 두 대화는 각각 196/196, 169/169개의 온전한 JSON을 확보했다.

- raw: 원문 focus만 읽는다.
- normalized: 인용 문자열 검증을 통과한 생성 문장을 원문 앞에 붙인다.
- supported: 인용 원문만으로 지지된다고 판정한 문장만 붙인다.
- dependent: 지지 판정을 통과하고, 인용을 제거하면 INSUFFICIENT인 문장만 붙인다.

각 unit의 본문은 기존 본문 토큰 수를 넘지 않게 문장을 순서대로 추가한다. 원문 focus 자체가 그 상한보다 길면 자르지 않고 기존 payload를 유지하며 fallback으로 기록한다. 사실 문장이 이웃 턴을 인용하면 해당 출처 ID를 provenance에 추가한다. 검색 키는 전부 동일하므로 BM25/dense 검색 순위는 같지만, 본문 길이에 따라 2048토큰 읽기에 포함되는 unit은 달라진다.

변경 본문과 기존 검색 키를 모두 저장하므로 기존 최고와 저장량이 같지는 않다. 저장 상한은 기존의 두 배이며 실제 비용과 fallback 수를 보고한다. 모든 생성 문장과 네 메모리를 고정한 뒤 동일 75개 source 사실의 Q0/A로 선택하고, 그 선택을 고정한 뒤 개발 70문항을 평가한다. 이미 소비한 audit100과 노출된 B 표현은 사용하지 않는다.

주변 문맥을 이용한 구성의 관련 사례로 [Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)이 있다. 그 방법은 문맥을 검색 표현에 추가하는 반면 이번 비교는 검색 키를 고정한다. 반사실적 입력 변화로 attribution의 충실도를 평가하는 관련 연구로 [Connecting Attributions and QA Model Behavior on Realistic Counterfactuals](https://aclanthology.org/2021.emnlp-main.447/)가 있다. 관련 방법 자체의 신규성은 주장하지 않는다. 실제 질문 답 보존으로 이어지는지 대조군으로 검증한다.
