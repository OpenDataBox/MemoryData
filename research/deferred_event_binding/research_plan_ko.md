# Deferred Event Binding: 연구 제안

작성일: 2026-09-07. 상태: 아이디어와 프로토콜 설계 완료, 구현·학습·실험 전. 명칭은 작업용이다.

## 추천하는 핵심

**새 대화를 어느 사건에 붙일지 애매하면 여러 연결 가능성을 기억에 남긴다. 현재 질문의 답이 그 연결에 따라 달라질 때, 연결을 구별하는 원문에 계산을 쓴다.**

새로운 요약 계층이나 원문 포인터를 기여로 내세우지 않는다. 검증할 후보 기여는 **지속되는 사건 연결 불확실성 + 답에 미치는 영향에 따른 보존·해소 예산 배분**이다. 검색 범위 내에서 차별화할 여지가 있는 연구 가설이며, 선행연구가 전혀 없는 아이디어라는 판정은 아니다. 불확실한 coreference와 adaptive retrieval 자체는 기존 기법이다.

## 작은 예시

| 관측 | 확실히 아는 내용 | 아직 불명확한 내용 |
|---|---|---|
| “박물관과 로봇 연구실에 지원했어.” | 서로 다른 지원 두 건이 있다. | 각 지원의 진행 상황 |
| “그 면접이 금요일로 미뤄졌어.” | 언급된 면접의 변경 날짜는 금요일이다. | 어느 지원의 면접인지 |
| 나중에 “연구실은 답이 없고, 금요일 면접은 박물관이야.” | 박물관 면접이라는 연결이 해소된다. | 이 연결에 대해서는 해소됨 |

두 번째 관측 시점에 “미뤄진 면접은 무슨 요일?”은 답할 수 있다. “어느 기관의 면접?”은 현재 근거만으로 확정할 수 없다. 세 번째 관측 이후에는 두 질문 모두 답할 수 있다. **아직 제공되지 않은 세 번째 발화를 앞선 시점의 메모리나 정답에 사용하면 안 된다.** 쿼리 시점 원문 확장은 이미 관측했지만 작은 쓰기 문맥이나 추출 표현에서 충분히 반영하지 못한 근거를 확인한다.

## 최소한으로 구현할 방법

1. **관측 저장.** raw span, 발화 시각, 발화자, 명시적 기관·인물·시간 표현을 기록한다. 관측 시각과 사건 시각은 다른 필드다. 추출물은 원문에 연결하며, 대명사를 추측해 실명으로 덮어쓰지 않는다.
2. **대안 연결 보존.** 새 event mention에 대해 기존 사건 후보와 새 사건 후보를 만든다. 연결 점수와 제약을 저장하고, 애매한 국소 부분에만 여러 유효 assignment를 유지한다. 발화에 사건이 둘이면 mention을 나눈다. 별개 사건 사이의 관련성은 동일 사건 관계와 구분한다.
3. **일관된 해석 구성.** 같은 사건이라는 관계의 추이성 등을 만족하는 assignment를 구성한다. 서로 배타적인 연결을 한 사실 묶음에 동시에 넣지 않는다. 복제하는 것은 원문이 아니라 작은 연결 구조다. 단일 tree cut만으로 표현할 수 없는 교차 대안도 평가한다.
4. **질문별 민감도.** 같은 후보 원문 풀에 대해 assignment별로 답을 구성하고, 의미상 답이 달라지는지 비교한다. 가설 연결은 가설임을 표시하며 원문과 같은 증거 권한을 주지 않는다. 질문 때문에 연결 점수 자체를 유리한 답 쪽으로 바꾸지 않는다.
5. **근거 선택.** controller가 질문, 읽은 원문, 연결 대안, 아직 안 읽은 단위의 메타데이터로 다음 확인 단위를 선택한다. 실제 원문을 먼저 읽고 그 비용을 숨기는 방식은 금지한다. 연결을 판별할 근거가 없으면 미해결로 남긴다.

먼저 mention graph와 작은 beam으로 구현해 타당성을 본다. 전체 사건 partition을 열거하는 설계는 피한다. 대안 수·보존 토큰을 제한하되, 가지치기를 하면 올바른 해석을 버릴 수 있음을 명시한다. 유지한 대안이 모두 같은 답을 낸다는 이유만으로 완전성을 주장하지 않는다.

## 학습 문제

연결 scorer는 개발 데이터의 event-binding annotation 또는 검수한 약한 라벨로 학습한다. scorer 점수를 정규화한 값은 초기에는 **가중치**이며, 보정 검증 없이 정확한 posterior라고 부르지 않는다.

질문 q, 실제 읽은 근거 E, 유지된 유효 assignment z와 가중치 w_z를 두고, 고정 reader가 산출한 답을 a_z(q, E)라 하자. 질문별 구조적 불일치의 간단한 측정치는 다음과 같다.

D(q,E) = Σ_z Σ_z' w_z w_z' d(a_z(q,E), a_z'(q,E))

d는 의미상 답의 비일치 정도다. 표면 문자열 차이와 의미 차이를 구분해야 하며, 고정 grader의 일부를 사람이 검수한다. D는 **유지된 대안에 대한 민감도**이지 실제 오류 확률이 아니다. 생성기 자체의 불확실성과도 구분한다.

controller의 학습 목표는 개발 질의에서 다음 효용의 기대값을 높이는 것이다.

J = E[answer_utility - λ_s × retained_state_cost - λ_r × total_read_cost]

실제 label에는 정답 외에 근거 귀속과 적절한 보류를 포함한다. 답 비교용 여러 reader 호출, planner, grader를 운영 때 사용하면 모두 read cost에 포함한다. 학습 데이터 작성에 쓰는 teacher 비용은 별도 보고한다.

초기 구현에서는 가능한 evidence-inspection action을 개발 데이터에서 실행해 얻은 utility 차이로 작은 action-value model을 학습한다. 운영 시에는 읽기 전 feature로 값을 예측한다. 연결 scorer와 controller를 구분해, controller가 답의 불일치를 낮추려고 불편한 가설을 삭제하는 편법을 막는다. 가설 삭제는 관측된 근거와 명시적인 용량 규칙으로 결정하며, 삭제에 따른 유효 assignment 누락률을 따로 측정한다.

보존 controller는 새 불확실성이 들어왔을 때 해당 대안을 유지할 효용을 개발 이력의 후속 질문으로 학습한다. 미래 질문은 **훈련 supervision**에만 사용할 수 있다. 테스트 이력은 시점별로 처리하며 실제 미래 질문·정답을 쓰기나 구조 생성에 입력하지 않는다.

## ICLR용으로 성립하려면 먼저 확인할 실험

**첫 관문: 이 오류가 실제로 얼마나 있는가.** 자연 대화 QA에서 raw evidence가 후보 풀에 모두 있는 사례를 모아, 틀린 답 중 사건 귀속 오류의 비중을 검수한다. 없거나 드물면 이 방향의 중심 가설이 약하다. 합성 데이터에서만 큰 차이가 나면 자연 대화 전반의 향상으로 쓰지 않는다.

**두 번째 관문: 단순한 대안으로 해결되는가.** 같은 writer, source pool, reader를 고정하고 아래 방법을 비교한다.

| 대조군 | 반박할 설명 |
|---|---|
| 즉시 하나로 연결 | 대안 유지에 실제 효과가 있는지 |
| 보수적인 merge threshold | 단지 덜 합치면 되는지 |
| 모든 관측을 분리하고 query-time에 연결 | 대안을 장기 보존할 이유가 있는지 |
| 단일 구조를 split/merge로 재편 | 수정을 허용하는 것만으로 충분한지 |
| uncertainty-aware coreference 후 최종 하나로 확정 | 기존 구조적 불확실성 추정만으로 충분한지 |
| 같은 대안 수를 무작위·연결 entropy로 보존 | 답에 미치는 영향을 학습할 필요가 있는지 |
| 같은 source pool의 강한 reranker / 원문 추가 | 검색·문맥 증가 효과인지 |
| 일반 confidence·entropy 기반 확장 | 구조적 불일치라는 신호가 추가 가치를 가지는지 |
| 대안별 답 비교는 하되 persistence를 제거 | 단순 test-time ensemble 효과인지 |

**세 번째 관문: 총비용이 같은가.** 원문 토큰뿐 아니라 연결 대안, 보존 메타데이터, writer, 각 대안 reader, 선택 controller의 토큰·호출·지연을 함께 잰다. 원문만 같은데 reader를 여러 번 돌리는 비교는 주 비교로 쓰지 않는다. 같은 총비용에서 단일 구조 baseline에 더 많은 raw context 또는 추가 추론 기회를 줘야 한다.

## 데이터와 분리

자연 대화의 LoCoMo·LongMemEval 전체 평가는 기존 프로토콜을 유지한다. 그 위에 사건 귀속이 필요한 문항을 독립 annotation으로 표시한다. 자연 데이터에 없는 구조적 라벨을 있는 것처럼 가정하지 않는다. 같은 사용자·대화의 문항이 train/test로 갈라져 누출되지 않도록 대화 단위로 분리한다.

보완용 controlled set은 반복된 활동, 같은 인물의 별개 지원·예약, 대명사, plan/outcome 구분, 늦게 도착한 명시적 설명을 포함한다. 기관 이름이나 날짜 하나를 바꿔 사건 연결만 바뀌는 paired histories와, 바꾸어도 답이 유지되는 control questions를 만든다. template, entity, paraphrase family까지 분리한다. 자연 문항, 합성 문항, 아직 답할 수 없는 prefix 문항 점수는 따로 낸다.

평가 단계는 (a) source 후보 풀 고정, (b) gold evidence 포함 조건, (c) 실제 end-to-end retrieval로 나눈다. 원문이 없는 오류, 잘못 묶은 오류, reader 오류를 섞지 않는 것이 핵심이다. source pool이 고정된 실험에서는 모든 baseline에 동일한 후보 정보가 제공되는지 확인한다.

## 보고할 지표와 중단 조건

정답률·근거 귀속 정확도, 해석에 따라 답이 달라지는 문항의 오류율, 적절한 보류의 risk-coverage curve, 유효 assignment 포함률, 가지치기로 잃은 정답 해석 비율, 늦은 설명 후 복구율, 총비용을 보고한다. 반복 실행은 동일 seed와 짝지어진 질문으로 비교하고 confidence interval은 대화 단위 상관을 반영한다.

다음이면 중심 주장을 축소하거나 버린다: 강한 reader가 원문 풀만으로 오류를 대부분 해결한다; 개선이 합성 문항에만 있다; 비용을 맞추면 효과가 사라진다; 단순한 낮은 merge threshold나 기존 uncertain coreference와 차이가 없다; 유효 해석 누락이 잦아 대안 합의가 오히려 과신을 만든다.
